環境構築方法

推奨動作環境(主要な項目のみ)

本シミュレータの推奨動作環境は以下の通りである。

  • OS : Ubuntu 22.04 LTS
  • Boost : 1.88.0
  • cereal : 1.3.2
  • CMake : 3.22.1 (>=3.10)
  • Doxygen : 1.14.0 (取扱説明書を生成する場合のみ)
  • Eigen : 3.4.0
  • gcc : 11.4.0 (C++20)
  • gymnasium : 0.28.1〜1.0.0 (rayのバージョンに依存する)
  • Magic Enum C++ : 0.9.7
  • nlohmann's json : 3.12.0
  • NLopt : 2.7.1
  • pybind11 : 2.13.6
  • Python : 3.10
  • PyTorch : 2.7.0 (>=2.1.0)
  • ray[default,tune,rllib] : 2.7.0〜2.46.0
  • thread-pool : 5.0.0

上記のうちC++依存ライブラリの一覧は C++依存ライブラリの一覧 に記載している。

インストール方法(Dockerを使用する場合)

ユーザ情報の指定

docker-compose.ymlの各サービスのbuild argsについてUSER_ID, GROUP_ID, REMOTE_USER, REMOTE_GROUPを任意の値に設定する。 少なくともIDはホスト側での自身のID(id -u及びid -g)と一致させることを推奨する。

ベースイメージの指定

docker-compose.ymlの各サービスのbuild argsについてBASE_IMAGEとBASE_TAGを任意の値に設定する。 GPUが不要なら例えばubuntu, 22.04とすればよい。

シミュレータ及びプラグインのビルド

docker-compose.ymlのbuildサービスを用いるとシミュレータ及びプラグインをビルドし、./distに格納することができる。ビルドには長時間かかるため、もしビルド済のwheelを持っている場合は手動で./distに配置してこの手順を省略することを推奨する。ただし、ドキュメントの生成を行う場合はこの手順を実行してbuildのイメージを生成しておく必要がある。

# ビルド
docker compose build build
# ビルド済wheelをホスト側の./distにコピー
docker compose run --rm -u $(id -u):$(id -g) build

作業用コンテナの初期設定

docker-compose.ymlのworkサービスを学習・評価用の作業用コンテナとして用いることを想定している。 リモートデスクトップの追加やVS Codeとの連携等、必要に応じて適宜カスタマイズして使用すること。

# サービスの起動
docker compose up -d work
# コンテナに入る
docker exec -it work bash

上記のコマンドにより、このディレクトリが/workspaceにマウントされ、/workspaceがカレントディレクトリになった状態でコンテナに入ることができる。初回起動後はworkspace_setup.shを実行することで/workspace/venvに仮想環境を作成してその中にシミュレータ及びプラグインがインストールされる。

# 仮想環境の作成とインストール
bash ./workspace_setup.sh

一部のみ更新した場合の個別ビルド

上記のDockerによるビルドでは、docker/build_sim.shによりこのリポジトリに含まれる全てのプラグインがビルドされるため時間がかかるが、一部のみ更新した場合等は、これらのスクリプト中でinstall_all.pyの呼び方を変えると個別にビルド、インストールできる。install_all.pyで指定可能なオプションはこちらの通り。また、デフォルトではdocker-compose.ymlのbuild argsでASRC_BUILD_OPTIONSとして改行区切り文字列でinstall_all.pyへの共通オプションを指定できる。

あるいは、workコンテナの中で直接install_all.pyを実行してもよい。むしろ試行錯誤で頻繁にリビルドする場合はそちらの方が簡便である。

インストール方法(ホスト側で直接インストールする場合)

Python仮想環境の起動

　本シミュレータのビルドスクリプトは"python"コマンドでインタプリタを起動する仕様となっている。 そのため、venvやconda等を用いて仮想環境を利用することを推奨する。

cd your/path/to/create/virtual/env
python3 -m venv env_name
source env_name/bin/activate

setuptoolsのインストール

後述のインストール用スクリプトはビルド時にsetuptools>=62.4が必要なため、もし未インストールの場合は事前にインストールしておく。

pip install "setuptools>=62.4"

シミュレータのビルド・インストール

リポジトリ直下で、

python install_all.py -b -i -c # 本体部分
python install_all.py -b -i -p # core_plugins以下に存在するプラグイン全て
python install_all.py -b -i -u # user_plugins以下に存在するプラグイン全て
#python install_all.py -b -a #-aは-c -p -uを全て指定するのと同じ効果

の順に実行すると、本体、core plugin、user pluginの順にビルド・インストールされる。 -bオプションはwheelをビルドするものであり、既存のwheelを使用する場合はこれを省略することでリビルドせずインストールのみを行える。 また、リビルドの際には--cleanを付けて一時ファイルを一度削除することを推奨する。

深層学習用フレームワークのインストール

シミュレータ及びサンプルの全ての機能を使用するためにはPyTorchとTensorflow(Tensorboard)が必要であるため、 各ユーザーは自身の所望のバージョンのこれらのフレームワークを別途インストールしておく必要がある。 なお、PyTorchについては一部のプラグインのrequirementsに含まれているため、未インストールだった場合はpip経由で 自動的にインストールされる。

第5回空戦AIチャレンジ用サンプルのビルド・インストール

リポジトリ直下で、-mオプションをつけて

python install_all.py -b -i -m "./sample/modules/r8_contest_sample"

を実行するとr8_contest_sampleパッケージがuser pluginとしてインストールされる。

ドキュメントの生成

Dockerを使用する場合

docker-compose.ymlのbuildサービスのコンテナが手元に存在している場合、以下のコマンドによりドキュメントをdoc/html以下に生成できる。トップページはdoc/html/core/index.htmlである。

docker compose run --rm -u $(id -u):$(id -g) -v .:/$(basename $(pwd)) build bash -c "source /opt/data/venv/bin/activate && cd /$(basename $(pwd)) && bash doc/scripts/clean_docs.sh && bash doc/scripts/generate.sh"

Dockerを使用しない場合

Doxygenのインストール

本シミュレータはC++20の機能を使用しているため、Ubuntu 22.04のaptリポジトリから得られるDoxygenでは正しくドキュメントを生成できない。最新版のバイナリをGitHub等からダウンロードしてインストールすること。

# graphviz、pdf2svgをインストール
sudo apt-get install -y graphviz pdf2svg
# LATEXをインストール
sudo apt-get install -y texlive-lang-japanese texlive-latex-extra texlive-luatex evince
# LATEXのインストール中に、
# "Pregenerating ConTeXt MarkIV format. This may take some time..."
# というメッセージが出たところで止まってしまう場合、
# Enter を連打(長押し)することでインストールが完了する。
# Doxygenの最新版のバイナリをダウンロード
curl https://github.com/doxygen/doxygen/releases/download/Release_1_14_0/doxygen-1.14.0.linux.bin.tar.gz -o doxygen-1.14.0.linux.bin.tar.gz -L
tar -xf doxygen-1.14.0.linux.bin.tar.gz
cd doxygen-1.14.0
sudo make
sudo make install

ドキュメント生成スクリプトの実行

上記のインストールが完了した後、仮想環境を起動した状態で、以下を実行するとdoc/html以下にドキュメントが生成され、そのトップページはdoc/html/core/index.htmlとして生成される。

bash ./doc/scripts/generate.sh

第5回空戦AIチャレンジ用サンプルの動作確認

シミュレータ本体の動作確認

sample/scripts/R8Contest/MinimumEvaluationに移動し、

python evaluator.py "Rule-Fixed" "Rule-Fixed" -n 1 -v -l "./result"

を実行すると、オープン部門のシナリオでルールベースの初期行動判断モデルどうしの戦闘が可視化しながら1回行われ、その結果を保存したログが./resultに保存される。GUIの無い環境で使用したい場合は、-vのオプションを省略することで可視化を無効化できる。 ユース部門のシナリオで実行したい場合は-yオプションを指定する。

HandyRLを用いた学習のサンプル

学習の実施

sample/scripts/R8Contest/HandyRLSampleに移動し、

python main.py R8_contest_open_sample_M.yaml --train

を実行すると、オープン部門のシナリオで1体で陣営全体を操作する行動判断モデルについて、Self-Playによる学習が行われる。 学習結果は./results/Open/Multi/YYYYmmddHHMMSS以下に保存される。 なお、"M"を"S" に変更すると、1 体で1機を操作する行動判断モデルとなり、保存先は"Multi"の代わりに"Single"となる。 また、ユース部門の場合は上記のopen,Openをyouth,Youthと読み替えること。

学習済モデルの評価

学習済モデルは、./results/Open/Multi/YYYYmmddHHMMSS/policies/checkpoints以下に保存されている。 このモデルの評価は上記のevaluator.pyを使用することで可能である。 sample/scripts/R8Contest/MinimumEvaluation/candidates.jsonを開き、例えば

"test":{
"userModuleID":"HandyRLSample01M",
"args":{"weightPath":"<学習済の.pthファイルのフルパス>"}
}

のように候補を追加し、sample/scripts/R8Contest/MinimumEvaluation上で

python evaluator.py "test" "Rule-Fixed" -n 10 -v -l "eval_test.csv"

と実行すると、初期行動判断モデルとの対戦による学習済モデルの評価を行うことができる。 ユース部門の場合は上記のopen,Openをyouth,Youthと読み替えること。また、-yオプションの指定を忘れないこと。

アンインストール方法

pip uninstallでもよいが、プラグインを一括でアンインストールするためのスクリプトuninstall.pyを用意している。

python uninstall_all.py -u # user plugin全て
python uninstall_all.py -p # core plugin全て
python uninstall_all.py -c # 本体部分
#python uninstall_all.py -a #-aは-c -p -uを全て指定するのと同じ効果
